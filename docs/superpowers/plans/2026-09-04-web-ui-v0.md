# Misaka Web UI v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a separately run Axum API and React/Mantine Sister Console that exposes the current local Misaka Network without bundling frontend assets into the backend binary.

**Architecture:** Add a cloneable `SisterHandle` in `misaka-runtime`, a new `misaka-api` crate that maps runtime snapshots into stable HTTP DTOs, and a `web/` Vite SPA that consumes only `/api/v1` JSON. `misaka start` launches the API on loopback beside the existing runtime; the frontend is started and built independently.

**Tech Stack:** Rust 2021, Axum 0.8, Tokio, Serde, tower-http, tracing, React, TypeScript, Vite, Mantine, TanStack Query, React Router, Tabler Icons.

**Spec:** `docs/superpowers/specs/2026-09-04-web-ui-v0-design.md`

## Global Constraints

- Misaka remains decentralized: every runtime node is a Sister; no master/slave role is introduced.
- `misaka-api` must use a runtime facade and must not read runtime store files, call the CLI, or reuse the external introspection protocol as its application contract.
- The API is loopback-only by default and rejects non-loopback bind addresses.
- The frontend is a separate Vite project and is never bundled into `misaka` in v0.
- The frontend uses Mantine, TanStack Query, React Router, and Tabler Icons; do not add Redux, Zustand, Axios, Tailwind, shadcn/ui, or a second UI framework.
- New behavior is test-first: write a focused failing test, run it, implement the minimum, and rerun the test before refactoring.
- Existing workspace dependency direction and Testament isolation remain unchanged.
- Keep secrets, private keys, membership material, and authorization tokens out of API responses and frontend code.
- Make one snapshot commit at the end of each task.
